## CRITICAL Issues

### W-1: Country defaults to USA for Canadian platform
**Source:** Wizard Step 2 (League Info)
**File:** `apps/league-builder/src/lib/schemas/league-wizard.ts:458`
**Description:** The league country defaults to `'USA'` in the wizard's `defaultValues`, despite this being a Canadian platform (`beerleaguehockey.ca`). Step 1 (Org Info) correctly defaults to `'CA'`, creating an inconsistency.
**Impact:** Every new Canadian league owner must manually change the country dropdown from USA to Canada.
**Fix:** Change line 458 from `country: 'USA'` to `country: 'CA'` and update timezone default from `'America/New_York'` to `'America/Toronto'`.

### W-2: Registration type mapping is confusing but functionally correct
**Source:** Wizard - createLeague server action
**File:** `apps/league-builder/src/lib/actions/league-wizard.ts:572`
**Description:** The `registrationTypeMap` maps both `'open'` and `'approval_required'` to `'open_registration'` in the DB. This looks like a bug but is actually correct — the approval logic is handled separately via `settings.requireApproval` (line 468). However, the architecture is confusing and could mislead future developers.
**Impact:** Low — functionally correct but architecturally confusing.
**Fix:** Add a code comment explaining this design decision. Consider adding `approval_required` to the DB enum for clarity.

### S-1: Homepage returns blank page when league not found
**Source:** Site - Homepage
**File:** `apps/league-sites/src/app/[leagueSlug]/page.tsx:61-62`
**Description:** When a league slug doesn't match any league, the page returns `null` instead of calling `notFound()`, resulting in a blank white page with no error message.
**Impact:** Users visiting an invalid league URL see nothing — confusing and unprofessional.
**Fix:** Import `notFound` from `next/navigation` and replace `return null` with `notFound()`.

## HIGH Issues

### W-3: Missing Canadian timezone options
**Source:** Wizard Step 2 (League Info)
**File:** `apps/league-builder/src/components/league-wizard/steps/step-2-league-info.tsx`
**Description:** The timezone selector defaults to `America/New_York` and may not prominently feature Canadian timezones (America/Halifax, America/Toronto, America/Winnipeg, America/Edmonton, America/Vancouver, America/St_Johns).
**Impact:** Canadian league owners have to search through a potentially US-centric timezone list.
**Fix:** Ensure all major Canadian timezones are listed first when country is set to 'CA'.

### W-4: Wizard step count mismatch
**Source:** Wizard container
**File:** `apps/league-builder/src/components/league-wizard/wizard-container.tsx`
**Description:** CLAUDE.md documents a 7-step wizard, but the schema defines 8 steps (1: Org Info, 2: League Info, 3: Season, 4: Teams, 5: Website, 6: Add-ons, 7: Payments, 8: Review). The progress indicator may show incorrect step counts.
**Impact:** User confusion about progress through the wizard.
**Fix:** Ensure step counter, progress bar, and documentation all agree on 8 steps.

### S-2: Scores page does not exist
**Source:** Site - Scores
**File:** `apps/league-sites/src/app/[leagueSlug]/scores/page.tsx` (MISSING)
**Description:** The homepage links to `/scores` and ScoresFilters component exists, but there is no actual scores page. Users clicking "Scores" get a 404.
**Impact:** One of the main navigation links leads to a dead page.
**Fix:** Create a scores page using `getScores()` from data.ts, with date grouping, team/season filters, and the existing ScoresFilters component.

### S-3: Schedule page returns blank on missing league
**Source:** Site - Schedule
**File:** `apps/league-sites/src/app/[leagueSlug]/schedule/page.tsx:57`
**Description:** Same issue as S-1 — returns `null` instead of `notFound()`.
**Impact:** Blank page instead of proper 404.
**Fix:** Import `notFound` from `next/navigation` and replace `return null` with `notFound()`.

## MEDIUM Issues

### W-5: orgBusinessName marked required but schema allows empty
**Source:** Wizard Step 1 (Org Info)
**File:** `apps/league-builder/src/lib/schemas/league-wizard.ts:8-11`
**Description:** The form field is marked as `required` in the UI, but the Zod schema only requires min 2 chars. The label says "Business/Organization Name" with a required indicator. However, some solo league organizers may not have a business name.
**Fix:** Either make it truly optional or add helper text explaining it can be a personal name.

### W-6: Season dates use string inputs instead of date pickers
**Source:** Wizard Step 3 (Season & Scorekeeping)
**File:** `apps/league-builder/src/components/league-wizard/steps/step-3-season-settings.tsx`
**Description:** Season start/end dates and registration dates use text string validation, which may render as plain text inputs rather than proper date pickers on some browsers.
**Fix:** Ensure `<input type="date">` is used for date-only fields.

### W-7: Default visible pages missing key pages
**Source:** Wizard Step 5 (Website)
**File:** `apps/league-builder/src/lib/schemas/league-wizard.ts:478-487`
**Description:** Default `visiblePages` has `news: false`, `history: false`, `gallery: false` — but doesn't include `scores`, `players`, `suspensions`, or `venues` which are valid pages. New league owners won't know these pages exist unless they explore the toggles.
**Fix:** Add all available page options to the defaults with sensible on/off values.

### W-8: Scorekeeping mode defaults to self_scorekeeping
**Source:** Wizard Step 3 (Season & Scorekeeping)
**File:** `apps/league-builder/src/lib/schemas/league-wizard.ts:467`
**Description:** Default is `'self_scorekeeping'` but most organized leagues want `'standard'` with assigned scorekeepers. Self-scorekeeping is the simpler option but may confuse league owners who expect professional scorekeeping setup.
**Fix:** Consider defaulting to `'standard'` or adding clearer descriptions of each mode.

### S-4: Game detail page doesn't handle missing season
**Source:** Site - Game Detail
**File:** `apps/league-sites/src/app/[leagueSlug]/games/[gameId]/page.tsx:76-85`
**Description:** Fetches season data using `game.season_id` without checking if it exists. If a game has no season, the RPC calls may fail silently.
**Fix:** Add null check: `if (!game.season_id) { /* skip season-dependent sections */ }`.

### S-5: Standings empty state doesn't distinguish teams vs games
**Source:** Site - Standings
**File:** `apps/league-sites/src/app/[leagueSlug]/standings/page.tsx:53-67`
**Description:** Shows "Standings will appear once games have been played" for both "no teams" and "teams but no games" scenarios.
**Fix:** Check team count first and show appropriate message for each scenario.

## LOW Issues

### W-9: No auto-slug generation preview
**Source:** Wizard Step 2 (League Info)
**Description:** League owners don't see what their league URL slug will be (e.g., `hockey-life-hl.beerleaguehockey.ca`) until after creation. No preview of the generated slug.
**Fix:** Show a live preview: "Your league will be available at: {slug}.beerleaguehockey.ca"

### W-10: No team color preview in bulk
**Source:** Wizard Step 4 (Teams)
**Description:** When adding multiple teams, there's no visual preview showing all team colors together to check for conflicts (e.g., two teams with similar colors).
**Fix:** Add a color swatch grid showing all entered team colors side by side.

### W-11: Payment step shows even when fees disabled
**Source:** Wizard Step 7 (Payments)
**Description:** If `enablePaidRegistration` is false, the Stripe Connect section still appears. The step could be auto-skipped when no paid features are enabled.
**Fix:** Auto-skip or collapse the payments step when no paid features are enabled.
